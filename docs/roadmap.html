Evidence-driven delivery

From hackathon MVP to dependable compute.

A roadmap is useful only when each milestone has an observable acceptance test. These phases describe what is implemented, what is being proven, and what is deliberately deferred.

Now · validate the MVP

Live, under validation

MCP Streamable HTTP, x402 exact payment negotiation, Celo USDC/USDT requirements, Cloudflare Sandbox execution, four MCP tools, an ERC-8004 agent card, and public documentation.

  • Run the paid scenarios with small mainnet ceilings.
  • Capture settlement hashes and latency percentiles.
  • Verify expiry, extension, release, and ambiguous settlement behavior.

Next · reliability

  1. Persist leases and payment/session correlation outside process memory.
  2. Add durable atomic refund reservations and idempotency keys.
  3. Add request correlation and structured metrics for payment, boot, exec, and release.
  4. Define output, duration, concurrency, and inactivity limits.

Later · product breadth

  1. Support deliberate runtime profiles or image versions.
  2. Evaluate metered billing only after facilitator and accounting support are proven.
  3. Add explicit artifact storage rather than implying sandbox persistence.
  4. Publish SDK examples for MCP clients and payment adapters.

When does a milestone move?

An item moves to complete only when a reproducible scenario, production observation, and documented failure mode exist. Passing the happy path alone is not evidence of reliability.
