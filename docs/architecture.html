How the system works

Two services, one paid execution loop.

The core service owns business logic and payment negotiation. The TypeScript Worker is a deliberately thin adapter around Cloudflare Sandbox.

System map

Agent
  │ MCP Streamable HTTP /mcp
  ▼
Go core ── verify / settle x402 on Celo ──► Facilitator
  │ authenticated /boot /exec /destroy
  ▼
Cloudflare Worker ──► Cloudflare Sandbox container
  │
  └── session-scoped stdout, stderr, exit code

Go core

services/core serves the MCP endpoint, agent card, landing page, session leases, payment requirements, facilitator calls, optional command safety checks, and refund review records.

The current lease store is in memory. A core restart can lose active lease records even if the adapter has not yet reclaimed the underlying sandbox. This is a known reliability gap, not a hidden guarantee.

Sandbox adapter

services/sandbox-adapter checks a shared secret and exposes three internal endpoints: /boot, /exec, and /destroy. The Worker uses one deploy-time container image. The request template is accepted for forward compatibility but does not select an image at runtime.

Identity and payment

The ERC-8004 agent card advertises the public MCP URL and payout wallet. x402 payment requirements are returned inside the JSON-RPC tool result. The MVP uses exact fixed-block settlement on Celo; it does not hold a payment-receiving private key.
