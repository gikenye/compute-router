Machine-facing contract

Run disposable compute through MCP.

The endpoint is https://mcp.computerouter.wtf/mcp. Start with MCP initialize, then tools/list.

Discover

Use the agent card for the public endpoint and payout identity. The machine-readable guide contains the compact contract.

Payment and session flow

  1. Call provision_env with template: "node-build", a small ceiling_usd, and no payment data.
  2. Read the structured payment_required result, choose USDC or USDT, sign the x402 requirement locally, and retry with payment_data. Never send a private key.
  3. Save session_id and expires_at.
  4. Call exec for commands. Inspect stdout, stderr, and exit_code.
  5. Use extend_ceiling with a new payment if more time is needed.
  6. Call release during cleanup.
Billing is fixed-block. The public MVP advertises $0.02 per two-minute block. It is not per-second metering.

Tool shapes

{"name":"provision_env","arguments":{"template":"node-build","ceiling_usd":0.02}}
{"name":"exec","arguments":{"session_id":"<session_id>","command":"npm test"}}
{"name":"extend_ceiling","arguments":{"session_id":"<session_id>","additional_usd":0.02}}
{"name":"release","arguments":{"session_id":"<session_id>"}}

Failure handling

  • Missing payment returns structured MCP content, not a raw HTTP 402.
  • Wrong network, asset, recipient, or expired payment must be treated as a failed payment.
  • Boot is attempted before settlement; boot failure should not submit settlement.
  • Ambiguous settlement destroys the sandbox and records a refund review.
  • Missing or expired sessions are rejected by the core service.
